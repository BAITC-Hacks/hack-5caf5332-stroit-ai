# Stroit AI — «Аким на 5 часов»

AI-симулятор управления Астаной: примите 5 решений в рамках бюджета и оцените их влияние на качество жизни районов и мнение синтетических жителей.

Единственный кейс команды на **HackAlem AI 2026**. [Публичная версия](https://sim-astana.diaskhalniyasov.workers.dev); для проверки достаточно локального запуска **без API-ключей**.

## Проблема и для кого

Городскому управленцу, аналитику и участнику симуляции нужно распределить ограниченный бюджет между транспортом, экологией, социальной инфраструктурой, безопасностью и сервисами. Симулятор показывает компромиссы: как улучшить общий результат, не оставив слабые районы позади, и какие решения поддерживают жители модели.

## Что умеет

Весь основной сценарий работает без ключа OpenAI:

1. Выберите **5 мер из 14** для районов Есиль, Алматы, Сарыарка, Байконур и Нура или нажмите **«Посмотреть готовый пример»**. Бюджет — **100 у.е.**
2. Проверьте план: ровно 5 уникальных мер, не более 2 из одного направления, корректное назначение районов, бюджет и конфликты. Движок учитывает синергии M1+M2, M10+M12, M5+M6; при нарушении правил балл не рассчитывается.
3. Откройте **«Итог плана»**: Astana Quality of Life Score, вклад каждого решения, «Сильные стороны / Риски / Последствия» и таблицу районов по 10 показателям через **8 кварталов**. Четыре цели: 5 решений по правилам, прирост балла минимум на 3, ни один район не стал хуже, меньше показателей ниже 40.
4. Посмотрите мнение **2 000 синтетических жителей**: 6 профилей интересов на район и долю поддержки по районам. **«Совет акима»** перебирает замены одного решения и показывает ориентир лучшего найденного плана.
5. Сравните результат после замены меры и поделитесь ссылкой на сценарий: план хранится в URL.

## Запуск за минуту без ключей

Нужен **Node.js 22+** и npm (проверено на Node.js 25). Из корня репозитория:

```sh
cd akim/ui
npm ci
npm run build
npm start
```

Откройте **http://127.0.0.1:8791** — UI и API работают вместе. Файл `.env` не нужен; сообщение **«OpenAI not configured»** ожидаемо и не мешает основному сценарию.

Для разработки после `npm ci` выполните `npm run dev`: UI — **http://127.0.0.1:5173**, API — **8791**. Интернет нужен для установки зависимостей, фоновой карты и обновления внешних данных; ключи проверяющего не требуются.

## Опционально: ключ OpenAI

Только для живых LLM-функций, из `akim/ui`:

```sh
cp .env.example .env
```

В локальном `.env` задайте `OPENAI_API_KEY` и перезапустите сервер. Не публикуйте файл с ключом и не используйте переменные `VITE_*` для секретов. Ключ остаётся на сервере и не попадает в браузер.

Модель **gpt-6-luna** через **OpenAI Responses** включает живого AI-акима с инструментами «симулировать», «спросить город», «предложить план», LLM-реплики жителей и **Ingest Threads** — поиск публичных постов по теме решения.

## Проверка

В отдельном терминале, из `akim/ui`:

```sh
npm test
npx playwright install chromium
npm run test:browser
```

`npm test`: **37 unit-тестов** движка, сервера, населения и планировщика, все проходят. Playwright проверяет интерфейс на desktop и mobile; браузерные тесты используют фикстуры API без платных вызовов.

В интерфейсе загрузите готовый пример: должны появиться 5 решений, расход бюджета, итоговый балл, четыре цели, вклад мер, таблица районов, поддержка жителей и локальный совет. Измените меру и проверьте пересчёт; нарушение бюджета или конфликт должны дать причину ошибки. Повторный ввод того же плана даёт тот же балл. В панели **«Данные города»** видны источники, даты и статусы записей.

## Как устроено

Код — [`akim/ui`](akim/ui). Стек: **React + TypeScript + Vite**, **Leaflet / OpenStreetMap**, **Canvas**, **Express API на tsx**. Публичный деплой — **Cloudflare Worker**.

| Слой | Роль |
| --- | --- |
| Движок | Проверяет правила, применяет эффекты, задержки и синергии; считает балл, показатели районов и вклад решений. Единственный источник чисел оценки плана. |
| Жители | 2 000 синтетических жителей; локальный расчёт поддержки и шаблонные реплики без ключа, LLM-реплики с ключом. |
| AI-аким | Без ключа — локальный совет с перебором замен; с ключом — агент, вызывающий инструменты и объясняющий проверенные результаты. |
| Реальные данные | API источников и датированные снимки; контекст для AI, не подмена синтетических индексов. |

**Числа оценки считает детерминированный движок; LLM объясняет и предлагает. Одинаковый ввод даёт одинаковый балл.** Формула учитывает средний результат города (70%), самый слабый район (30%) и штраф за каждый показатель ниже 40; детали — в [правилах](akim/file.md).

API:

- `GET /api/health` — состояние сервера и настройки модели; `GET /api/city` — данные города.
- `POST /api/ask` — опрос жителей; `POST /api/explain` — LLM-объяснение плана.
- `POST /api/akim` — AI-аким; без ключа режим `goal` работает локально со структурированным `constraints` (текстовая цель требует ключа).
- `POST /api/threads/ingest` — поиск публичных постов Threads, нужен ключ OpenAI.

## Данные

[ТЗ кейса](akim/tz.md) · [Датасет и правила](akim/file.md) · [Концепция продукта](akim/PROJECT.md) (содержит также планы развития).

Игровой датасет синтетический: 5 районов, 14 мер, 10 индексов **0–100**, где больше — лучше: T1/T2 — транспорт, E1/E2 — экология, S1/S2 — соцсфера, B1/B2 — безопасность, C1/C2 — сервисы.

Панель «Данные города» (`GET /api/city`) показывает:

- погоду **Open-Meteo** и качество воздуха **CAMS**;
- записи ДТП за **2026 год**, **KGP ArcGIS**;
- население **БНС: 1 528 703 на 31.12.2025**;
- реестр районов геопортала **map.gov.kz**.

У каждой записи есть источник, дата наблюдения и статус **live / cached / unavailable**. При недоступности источника используется датированный снимок либо явно показывается отсутствие данных; значения не выдумываются. Реальные данные дают контекст для AI и **не меняют синтетические индексы датасета**.

## Ограничения и что дальше

Датасет и жители синтетические, персональных данных нет; поддержка жителей — модель, а не реальный опрос. Карта реальная, но в игре 5 районов, а в реестре 6: **Сарайшык без игрового балла**. Стоимость мер — сценарная оценка, не смета. Локальный поиск не гарантирует глобально лучший план; Threads охватывает только доступные публичные посты.

Возможное развитие: калибровка эффектов мер на городских данных и расширение модели районов. Это направления дальнейшей работы, а не реализованные функции.
