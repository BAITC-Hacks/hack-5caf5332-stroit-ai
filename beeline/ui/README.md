# Beeline Campaign Studio

Интерактивный UI только для кейса Beeline: аудитория, пилоты, план кампаний. Кейс №11 сюда не входит.

## Запуск с агентом

Сервер поднимает UI и гоняет агента через `engine/run_case.py` в папке кейса:

```sh
cd beeline/ui
pip install -r requirements.txt
cp engine/run_case.py "../beeline_case_participants (1)/"
python3 server.py --engine "../beeline_case_participants (1)"
```

Открыть <http://127.0.0.1:4173>, кнопка запуска дёргает `POST /api/run`. Агент должен после `act(env)` оставить `self.audit` по контракту из `docs/AGENT_CONTRACT.md`; пример заполненного прогона в `docs/run.example.json`. `engine/agent.py` здесь только как эталон, который этот контракт выполняет; в сабмишен идёт агент из папки кейса.

## Открыть

Приложение не требует сборки или npm-зависимостей во время работы.

```sh
cd "/Users/ardan/Project Code/beeline-campaign-ui"
python3 -m http.server 4173 --bind 127.0.0.1
```

Открыть <http://127.0.0.1:4173>. Используйте HTTP-сервер, а не `file://`: маршрутизация и история используют URL.

## Что работает

- Аудитория: кандидаты в план, панель «Почему этот вариант», раскрываемый состав аудитории, поиск, фильтр, детали сегмента.
- Пилоты: фильтр канала, разбор наблюдения, демо-запуск с ожиданием, отменой и защитой от повторного запуска; лимит 20.
- План: два стартовых кандидата, объяснение выбора, явное подтверждение риска для непроверенных кампаний, пересчёт расходов вместе с пилотами, проверка лимитов, порядок через кнопки, CSV и JSON. Подтверждение риска сбрасывается при изменении выбора, перезагрузке и переходах между экранами.
- Состояния каждого экрана: данные, загрузка, пустой результат, ошибка с повторной загрузкой. Переключатель находится внизу страницы в раскрываемой панели «Проверка прототипа».
- Клавиатура: Tab / Shift+Tab, Enter, Space для checkbox, Escape для диалога, стрелки / Home / End для select. Есть skip link, видимый фокус, live-объявления и возврат фокуса.
- Выбор, порядок, фильтры и детали отражены в URL и переживают перезагрузку. Нет скрытого сохранения персональных данных.
- Адаптивный интерфейс, включая 375 px; поддержка reduced motion.

Прямые ссылки:

```text
/?screen=audience
/?screen=pilots
/?screen=plan
/?screen=plan&state=error
/?screen=audience&state=empty
/?screen=pilots&state=loading
/?screen=plan&selected=none
```

## Границы прототипа

Все сегменты, размеры, наблюдения и оценки — демонстрационные fixtures в `src/app.js`. Нет соединения с агентом, evaluator, API оператора или базой абонентов. Демо-пилот воспроизводит заранее заданный пример. Нет загрузки клиентских данных и реальных рассылок.

CSV `demo-submission.csv` соблюдает структуру полей задания, но не является готовой заявкой организатору. JSON явно содержит `demo: true` и ограничения расчёта. Оценка net относится только к финальным кампаниям; истинный общий эффект с пересечениями пилотов UI не вычисляет. Показанные диапазоны пилотов иллюстративные.

Канал и целевой тариф в карточках фиксированы в примере. Их редактирование, импорт аудитории, реальная адаптивная политика и интеграция с backend в эту реализацию не входят.

## Проверки

Для разработки и автоматического аудита:

```sh
npm ci --ignore-scripts
python3 -m pip install -r tests/requirements.txt
npm run check
npm run format
# В отдельном терминале должен работать локальный сервер; установлен Google Chrome.
python3 tests/test_ui.py
```

`tests/test_ui.py` использует отдельный профиль Chrome, не пользовательскую браузерную сессию. Проверяет 5 ширин, три экрана в четырёх состояниях, доступность через axe-core, клавиатурный сценарий, CSV/JSON и reduced motion. Скриншоты генерируются в `tests/results/`. Автоматический аудит не заменяет проверку со скринридером на реальном устройстве.

## Файлы и следующий шаг

- `index.html` — оболочка и диалог.
- `styles.css` — визуальная система и адаптивность.
- `src/app.js` — состояние, fixtures, расчёты UI и действия.
- `DESIGN.md` — обоснование дизайна по frontend-design.
- `AUDIT.md` — ревью каждого экрана по web-design-guidelines и результаты тестов.

Для подключения агента замените fixtures адаптером к audit/output из ТЗ Beeline. Валидацию реальных кампаний и вычисление эффекта оставьте серверу/evaluator; визуальные оценки UI не должны становиться источником истинных результатов.
