# Бриф для Codex: кейс 11 «Анализ оргструктуры и функционала»

HackAlem AI 2026, команда Stroit AI. Параллельный кейс: делаем полностью рабочий прототип, который запускается одной командой. Исходное ТЗ лежит в `TZ-original.txt`, данные в `data/`.

## Что строим одной фразой

Пользователь загружает две редакции документа («до» и «после» реорганизации). Сервис показывает, какие подразделения созданы, сохранены или преобразованы, какие функции потерялись, перенесены или задублированы. Каждый вывод подтверждён двумя дословными цитатами с номером пункта: из старой редакции и из новой.

Это не чат с документами, а доказательный semantic diff. Главный продуктовый принцип: **нет цитаты — нет вывода**.

## Экраны

1. **Загрузка.** Два слота «До» и «После» (DOCX, PDF, TXT, XLSX по возможности). Кнопка «Загрузить демо-комплект» подставляет редакции 8 и 9. Прогресс по шагам пайплайна.
2. **Сводка.** Счётчики: подразделений создано / сохранено / преобразовано / упразднено; функций сохранено / перенесено / переформулировано / потеряно / задублировано; найдено конфликтов интересов. Итоговое заключение в 5–7 предложений, каждое со ссылкой на пункт.
3. **Подразделения.** Схема «было → стало»: старые узлы слева, новые справа, линии переноса функций. Клик по узлу показывает его функции.
4. **Таблица функций.** Колонки: функция, было (подразделение, пункт), стало (подразделение, пункт), статус, уверенность, цитаты. Фильтр по статусу. Клик по строке открывает две цитаты рядом с подсветкой отличий.
5. **Риски.** Отдельно потери, дублирования, конфликты интересов (одно подразделение и проверяет, и исполняет; аудитор проверяет свою прежнюю зону). У каждого риска: почему это риск, две цитаты и рекомендация, как перераспределить.
6. **Как это работает.** Схема пайплайна и правило «нет цитаты — нет вывода», режим (детерминированный или LLM), время выполнения.
7. **Экспорт.** Заключение в DOCX или HTML с таблицей и цитатами, плюс JSON.

UI/UX: используй скиллы `frontend-design`, после каждого экрана прогоняй `web-design-guidelines`. Состояния загрузки, пустого результата и ошибки разбора обязательны. Работа с клавиатуры, ширина 375px. Язык интерфейса русский. Без emoji, только SVG-иконки.

## Логика (детерминированное ядро)

1. **Парсинг.** DOCX, PDF, TXT → список абзацев `{doc, section, clause, text}`. Нумерация пунктов регуляркой (`\d+(\.\d+)*\.`, буквенные подпункты `а.`, `б.`), склеенные пункты расклеивать, переносы внутри слов чинить, оглавление в конце отбрасывать.
2. **Подразделения.** Извлечь из перечней (п. 3.4 и аналогичных) и заголовков вида «Директор департамента …». Название плюс аббревиатура в скобках. Сопоставление старых и новых по аббревиатуре, затем по нормализованному названию. Статусы: `created`, `kept`, `transformed`, `abolished`.
3. **Функции.** Пункты внутри блоков ответственности подразделения (раздел 5 и аналогичные) — отдельные функции с владельцем.
4. **Сопоставление функций.** Сначала точное совпадение нормализованного текста, затем TF-IDF по словам и символам (cosine), затем опционально эмбеддинги или LLM-судья. Статусы:
   - `kept` — тот же владелец, текст почти совпадает;
   - `moved` — текст совпадает, владелец или номер пункта другой;
   - `reworded` — тот же смысл, формулировка изменена (сходство выше порога, но не точное);
   - `lost` — лучшее совпадение ниже порога. Всегда с пометкой «требует проверки»;
   - `added` — новая функция;
   - `duplicated` — в новой редакции у двух разных подразделений функции с высоким сходством.
5. **Конфликты интересов.** Правила: подразделение одновременно выполняет и контролирует одну функцию; упоминания «конфликт интересов» и нарушения независимости. Каждый конфликт с цитатами.
6. **Верификатор доказательств.** Любой вывод без двух дословных цитат, найденных в исходнике, выкидывается или помечается «не подтверждено». LLM не может добавить вывод, которого нет в детерминированном результате, только переформулировать.
7. **Заключение.** Шаблон по фактам. С ключом LLM переписывает его человечнее, после чего верификатор проверяет, что все пункты и цифры из фактов.

Пороги сходства вынести в конфиг и подобрать на демо-комплекте. Результат детерминирован: те же файлы — тот же отчёт.

## Контракт API

- `POST /api/analyze` (multipart: `before[]`, `after[]`) → `{ run_id, units[], functions[], risks[], conclusion, pipeline[], mode, elapsed_ms }`
  - `units[]`: `{ id, name, abbr, status, before_ref, after_ref }`
  - `functions[]`: `{ id, text, status, confidence, before: {unit, clause, quote}, after: {unit, clause, quote} }`
  - `risks[]`: `{ type: lost|duplicated|conflict, severity, explanation, recommendation, evidence[] }`
- `POST /api/demo` — тот же ответ на встроенном комплекте 8/9.
- `GET /api/export/{run_id}?format=docx|html|json`
- `GET /api/health`

Стек на выбор Codex, главное — один запуск: `npm start` или `python -m app` / `streamlit run`. Если есть Docker, добавить `docker compose up` как второй путь.

- повторный прогон даёт идентичный JSON.

Плюс синтетический комплект: скопировать редакцию 9, удалить один пункт функции и продублировать другой в соседнем департаменте. Агент обязан найти оба случая. Это наша репетиция «контрольного комплекта» жюри.
